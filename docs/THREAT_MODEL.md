# Dreigingsmodel — TeamBot

Versie 1 · 2026-11-06, bijgewerkt 2026-11-08 (T27 dicteren in elk programma, T28 teampakketten, T28b OpenBot-team
overzetten) en 2026-11-09 (0.4: pakket P "standaard dicht": T3, T7, T11 aangescherpt, nieuw T30 blootstelling en
eerste installatie, T31 wachtwoorden raden en sessies, T32 privacy per AI-dienst; pakket K: T33 kanalen met klanten;
pakket G: T1 externe inhoud en antwoorden van andere bots, T9 stoppen van hele procesbomen, T34 prullenbak,
goedkeuring alleen waar het telt en routines met bewijs). Herzien bij elke nieuwe module met externe invoer of acties
met impact, en vóór een publieke cloudlancering (dan ook een externe security review).

## 1. Wat we beschermen

| Bezit | Waar | Waarom gevoelig |
|---|---|---|
| Provider-sleutels, OAuth-tokens, kanaal-tokens, webhook-secrets | `secrets`-tabel (AES-256-GCM; hoofdsleutel via Windows DPAPI op de desktop, `master.key`/`TEAMBOT_MASTER_KEY` op een server) | Geld, toegang tot accounts van de gebruiker |
| Gesprekken, geheugen, dossiers, bijlagen | SQLite + `attachments/` in de datamap | Privé- en bedrijfsinformatie |
| Werkmappen van bots | `workspaces/<bot>` of door gebruiker gekozen map | Bestanden van de gebruiker |
| Host-computer (desktop) | Windows-pc van de gebruiker | Volledige controle bij misbruik van shell/host-bediening |
| Accounts op een gedeelde server | `users`, `sessions` | Data van vrienden/klanten moet gescheiden blijven |
| Beheerde cloud (CLD-04): cloudaccounts, abonnementen, hoofdsleutels van workspaces | Postgres van de control plane (`cloud/`); hoofdsleutels AES-256-GCM met `CLOUD_SECRET_KEY`, gebonden aan de workspace-id | Wie dit heeft, kan workspaces starten en hun sleutels lezen; betalingen en toegang van klanten |

## 2. Vertrouwensgrenzen

```
 [Browser/Electron-UI] --(Bearer-token, loopback of HTTPS)--> [TeamBot-server]
 [Telefoon (PWA/iOS)] --(apparaat-token, LAN/Tailscale/HTTPS)--> [TeamBot-server]
 [TeamBot-server] --> [AI-providers]  (prompt + context verlaat het apparaat)
 [TeamBot-server] --> [Tools: bestanden/shell/web/browser/MCP/kanalen]  (Broker = enige poort)
 [Internet: webpagina's, e-mail, webhooks, chatkanalen, MCP-uitvoer, skills] --> onbetrouwbare data
 Beheerde cloud:
 [Internet] --(HTTPS, Caddy)--> [Router] --(Host = <slug>.<domein>)--> [één TeamBot-instantie per klant]
 [Router] --(Host = <domein>)--> [Control plane] --> [Postgres]   [Stripe] --(ondertekende webhook)--> [Control plane]
 [Control plane] --(Docker-socket)--> [Docker-host]   (instanties: eigen netwerk, volume, sleutel, limieten)
 [Control plane] --(GET /healthz, alleen https + publiek adres)--> [Dedicated TeamBot in de VPC van de klant]
```

De **Broker** (`server/tools/broker.ts`) is de enige plek waar toolgebruik wordt toegestaan of geweigerd. Elke tool heeft
een eerlijk risico (`read`/`write`/`exec`/`danger`); de toegangsmodus van de bot en het per-tool-beleid bepalen of er
gevraagd wordt; `danger` vraagt altijd.

## 4. Gegevensstromen naar buiten

Alleen naar diensten die de gebruiker zelf koppelt: AI-providers (prompt + context + bijlagen die de bot meestuurt),
zoekdienst (zoekterm), MCP-servers/apps (tool-argumenten), kanalen (antwoorden), web-push-dienst van de browser
(versleutelde melding), een eigen server via SSH (opdrachten en bestanden van de bot) en een cloudprovider als de
gebruiker een cloud-VM laat maken (VM-aanvraag met de cloud-init van TeamBot; geen gesprekken of andere gegevens).
Geen telemetrie of analytics; crashrapportage alleen opt-in en geredigeerd. Per bot zegt een privacylabel wat de
AI-dienst met de gesprekken doet (T32); de pagina Gegevens zet al deze stromen voor de gebruiker op een rij
(**Wat verlaat je pc?**, `GET /api/privacy/overview`).
